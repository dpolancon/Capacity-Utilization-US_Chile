# Audit: Cointegration Test Triad & Coefficient Significance Stars, Section 3.1 IM-OLS Report

**Trigger**: user suspicion that significance stars in
`reports/US_Section31_IMOLS_Results/us_section31_imols_results_v2.pdf` (18-model IM-OLS matrix,
1929–2024, generated by `codes/US_S50_section31_imols_estimation.R`) might be misplaced.

**Verdict**: confirmed. Two independent defects found and fixed; one flagged as unresolved.

---

## 1. What was wrong

### 1.1 VW Type 2 ($S_{\text{Type 2}}$) critical values were hardcoded and unrelated to the actual test

`calc_vw_type2_stat()` computed a genuine Wald statistic $\hat\lambda_2' \hat V_2^{-1} \hat\lambda_2 /
\hat\omega^2$, then compared it to a single hardcoded triple — 10%/5%/1% = 11.45/13.78/18.90 — for
every one of the 18 models.

The real Vogelsang & Wagner (2014) fixed-$b$ critical values (retrieved from their own published
supplement, "Tables with Critical Values for Integrated Modified OLS Estimation and Fixed-b
Inference for Cointegrating Regressions," *Journal of Econometrics* 178(2), 741–760) are **not
constant**: they vary roughly 10-40x across the tabulated bandwidth-ratio range
$b=\text{bandwidth}/T \in [0.02, 1.00]$, and depend on $k$, the number of stochastic ($I(1)$)
regressors — this report mixes $k=2$ (no NetC control) and $k=3$ (with NetC control) models in the
same tables. The hardcoded triple matched no single $(b,k)$ cell of the real table.

### 1.2 Coefficient-level stars used naive standard-normal cutoffs, contradicting the report's own claimed methodology

`get_asterisks()` (dead code, never called) and `stars_from_coef_sd()` used plain 1.645/1.960/2.576
cutoffs for every coefficient ($\hat\alpha$, $\hat\gamma^{\text{step}}$, $\hat\theta_0$,
$\hat\theta_1$, $\hat\beta_{\text{cm}}$), while the report's own preamble claims "fixed-$b$ HAR
$t$-statistics." Genuine fixed-$b$ critical values for a single-coefficient test are systematically
**larger** than standard-normal ones — this is the entire point of fixed-$b$/HAR theory (Kiefer &
Vogelsang 2002, 2005): the bandwidth is held as a fixed fraction of $T$ rather than let vanish
asymptotically, which inflates the reference distribution relative to the standard normal limit.
Using the standard-normal cutoffs therefore **systematically overstated significance**.

### 1.3 Shin LM — flagged, not fixed

Same structural defect as §1.1 (fixed critical values applied regardless of $k$), but Shin's (1994)
original critical-value table could not be retrieved this session (source PDF had an expired TLS
certificate). Rather than fabricate corrected numbers, the existing fixed row (0.095/0.121/0.184)
was left in place with an explicit code comment and footnote caveat marking it as **provisional**.
This is the one open item from this audit.

### 1.4 Resid. ADF — checked, found correct

`cv_adf()` already varies the MacKinnon (2010) critical value by $m$ (number of $I(1)$ variables
including the dependent variable), matching the value already locked in
[[E17_Cointegration_Significance_Stars_Lock]]. No change made.

### 1.5 Minor issues also fixed
- Preamble claimed "$N=95$"; every table showed $N=94$. Root cause: `df_clean` (after listwise
  deletion for the lag-1 conditioning variables) has 94 rows, 1931–2024. The preamble now reports
  the true sample size and window dynamically rather than a stale hardcoded number.
- The footnote attributed *all* significance stars (coefficients and the full cointegration triad)
  to one generic "fixed-$b$ HAR $t$-statistic" basis. Reworded to state each row's actual
  critical-value source (MacKinnon EG-ADF; Shin 1994 [caveated]; Vogelsang-Wagner 2014 fixed-$b$,
  now genuinely $(b,k)$-indexed for both the VW Type 2 row and every coefficient row).
- `reports/US_Section31_IMOLS_Results/us_section31_imols_results.md`: an orphaned file with stale
  numbers from an earlier pipeline version (the script defines a path for it but never writes to
  it). Flagged with a warning banner rather than deleted; recommend deletion.
- Vault governance contradiction: [[E17_Cointegration_Significance_Stars_Lock]] banned the VW Type 2
  row as "mathematically invalid" while [[E15_Vogelsang_Wagner_IMOLS_Cointegration_Test_Lock]] (same
  `last_updated` date) declared it "PRIMARY & BINDING." Reconciled — the Wald quadratic-form
  implementation that shipped was never the Euclidean-norm shortcut E17 warned against; what needed
  fixing was the critical values, not the test's existence. See E17 §2-4 for the corrected text.

## 2. The fix

New module: `codes/COMMON_VW_fixedb_critical_values.R`. Digitizes the Vogelsang & Wagner (2014)
supplement (Bartlett kernel, intercept-only case — matches this pipeline's `deter` matrix of
intercept + step dummies, no trend) for:
- **t-test tables**, $k=1..4$ stochastic regressors (feeds coefficient stars),
- **Wald tables** (the "diagonal" case — all $k$ regressors' $\lambda_2$ jointly tested, matching
  this repo's VW Type 2 construction), $k=1..4$ (feeds the VW Type 2 row).

Both tabulated over the full $b \in \{0.02, 0.04, ..., 1.00\}$ grid; `fixedb_crit()` linearly
interpolates for a model's actual $b$, `fixedb_stars()` wraps this into a direct star-string
lookup. $k=1..4$ was chosen deliberately (not just the $k=2,3$ this report needs) so Section 3.2
and later work can reuse the same module without re-digitizing; extending beyond $k=4$ requires
digitizing the corresponding table from the same source (up to $k=10$ is available there for the
Wald case) rather than extrapolating.

Each model's actual bandwidth is read from `fit$bandwidth$number` (returned by
`cointReg::cointRegIM`, confirmed by direct package inspection this session — field structure
`list(name="Newey-West", number=<numeric>)`); $b_{\text{hat}} = \text{bandwidth}/T_{\text{obs}}$.

`US_S50_section31_imols_estimation.R` now sources this module and uses it in both
`calc_vw_type2_stat()` (VW Type 2 row) and `export_s50_latex_table()`'s `stars_from_coef_sd()`
(all coefficient rows). Scope was deliberately contained to this one script — the same hardcoded
critical values are duplicated in `COMMON_S40_baseline_imols_cpr_estimation.R` and copied into
roughly ten other scripts (S16-19, S22, S33 family, S41, S42B, S43); those were **not** touched by
this audit and still have the old defect. Migrating them to `COMMON_VW_fixedb_critical_values.R` is
a natural follow-up, flagged here rather than done silently as part of this fix.

or far above the tabulated critical-value range at its actual $(b,k)$, so the corrected numbers
happen to agree with the old (wrong) ones on which models get stars. The fix is still necessary —
the old numbers were not justified by any real methodology and could easily have flipped a verdict
for a model with a less extreme statistic (as the coefficient-level results below show did happen)

   should really share the stochastic-regressor fixed-$b$ table, or need a separate treatment.
